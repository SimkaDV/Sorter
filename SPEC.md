# 3D Models Sorter — спецификация

> Нативное приложение для macOS, которое наводит порядок в папке с 3D-моделями.
> Статус: проектирование завершено, далее MVP. Обновлено 21.11.2026.

---

## 1. Суть

Каталог моих 3D-моделей с превью, который **работает прямо с реальными папками на диске**: создаёт, перемещает, переименовывает и раскладывает файлы по единым правилам. Заметки и статусы пишет в txt рядом с моделями. Если приложение удалить, структура и заметки останутся.

**Главная фишка:** разбор свалки. Файлы из «Разобрать» группируются в модели с версиями, переименовываются по правилу и раскладываются по папкам в пару кликов.

## 3. Система хранения

### 3.1 Структура

```
3D Models/
  Скачанные/                         ← чужие модели (пока второстепенно)
  Мои модели/
    _Разобрать/                      ← входящие, свалка
    Для дома/                        ← категория
      Кухня/                         ← категория (вложенность любая)
        Держатель досок/             ← одиночная модель
          Держатель досок.f3d
          Держатель досок.txt
          Держатель досок – v3.stl
          Держатель досок – v3.3mf
          Версии/
            Держатель досок – v2.stl
    Канцелярия/
      Кейсы/                         ← коллекция
        Кейсы.f3d                    ← один Fusion на коллекцию, без версий
        Кейсы.txt                    ← описание коллекции и её моделей
        Кейсы набор.3mf              ← один общий 3MF на набор
        Крышка левая – впуклая 2мм – Кейсы – v3.stl   ← деталь коллекции
        Крышка правая – Кейсы – v2.stl
        Версии/                      ← одна на всю коллекцию, включая группы
        Крышки/                      ← группа
          Крышка с рамкой – Кейсы – v4.stl
    Разное/                          ← категория для моделей «ни к чему»
```

### 3.2 Типы папок и как их отличать

| Тип | Что это | Как определяется |
|---|---|---|
| Корень | `Мои модели`, `Скачанные` | фиксированные папки |
| Разобрать | входящие | `_Разобрать/` |
| Категория | тематическая папка («Для дома», «Канцелярия») | любая папка без пометки «Коллекция»/«Модель» |
| Коллекция | набор деталей с одним Fusion-файлом | в шапке txt: `Тип: Коллекция` (кнопка «Сделать коллекцией») |
| Группа | подпапка внутри коллекции для однотипных деталей | любая папка внутри коллекции |
| Модель | одиночная модель: коллекция из одного элемента | в шапке txt: `Тип: Модель` |
| Версии | старые версии | папка `Версии/`, в дереве скрыта |

- Коллекция может лежать внутри категории (`Для дома/Кухонный набор/`).
- **Модель = коллекция из одного элемента.** Та же структура: свой F3D, 3MF, STL, txt и `Версии/`. В UI показывается карточкой модели, а не папкой. Если добавить второй элемент, она становится коллекцией.
- Деталь внутри коллекции — это файлы (STL и/или 3MF одной версии), без своей папки и без своего F3D: она ссылается на F3D коллекции.

### 3.3 Имена файлов

```
<Название> – <Параметры> – <Коллекция> – <Версия>.<ext>
```

- Пустые части пропускаются: `Крышка правая – Кейсы – v2.stl`, `Держатель досок – v3.stl`.
- Версии: `v1`, `v2`, `v2.1`, `v10` (Finder сортирует их естественно, ведущие нули не нужны).
- Разделитель — **среднее тире с пробелами ` – `** (U+2013). В коде это одна константа. При разборе старых имён понимаем также ` - ` и ` — `.
- Fusion-файл и txt называются по коллекции или модели: `Кейсы.f3d`, `Кейсы.txt`.
- Попутно чистим имена: пробелы в конце, двойные пробелы, Unicode NFC для кириллицы (`й` в двух формах).

### 3.4 Версии

- В основной папке лежит **только актуальная версия**. Старые лежат в `Версии/`: у одиночной модели — в её папке, у коллекции — **одна `Версии/` в корне коллекции** для всех деталей, включая детали из групп (у групп своей `Версии/` нет).
- Новая версия: перетаскиваешь файл на модель, приложение предлагает номер, предыдущая версия уезжает в `Версии/`, заметка дописывается в txt.
- **Очистка старых версий:** кнопка «Очистить старые версии» отправляет файлы из `Версии/` в Корзину macOS (их можно восстановить). Записи о версиях и заметки в txt остаются. В таймлайне такая версия помечается «файл удалён».

### 3.5 Статусы (теги)

У модели или детали ровно один статус:

| Статус | Цвет | Значение |
|---|---|---|
| В работе | синий | моделирую, не печатал |
| Тестируется | жёлтый | напечатал, проверяю |
| Готово | зелёный | доработана, эталон |
| Брак | красный | не получилось, не использовать |

- Хранится в двух местах: тег Finder на файле или папке **и** строка в txt.
- Существующий тег «Эталон» при миграции превращается в «Готово».
- Отдельно есть тег «Избранное» (звёздочка), тоже в Finder.
- ~~Печаталось / не печаталось~~ убрано: автоматически это не определить.

### 3.6 txt-файл

Один файл на коллекцию или модель. Приложение **читает шапку и дописывает журнал**, но никогда не переписывает то, что написано руками.

```
Тип: Коллекция
Название: Кейсы
Описание: Набор кейсов: портсигар, зажигалка, окурки. Магниты 6×2, PLA без поддержек.
Коллекции: Gridfinity

== Крышка левая
Статус: Готово

--- 2026-11-18 · v3
Паз под магнит 6.2, сел плотно.

--- 2026-11-12 · v2.1
Скруглил края, магнит болтается.

== Крышка правая
Статус: Тестируется

--- 2026-11-15 · v2
Под новую петлю.
```

Правила:
- Шапка — это строки `Ключ: значение` до первой пустой строки или `==`.
- `== Имя` — раздел детали (в файле модели разделов нет, журнал идёт сразу после шапки).
- `--- ДАТА · ВЕРСИЯ` — запись журнала. Новые записи добавляются наверх раздела.
- Неизвестные строки сохраняются как есть.

### 3.7 Заполненность

Считается для коллекции и модели:

| Признак | Условие |
|---|---|
| Fusion ✓ | есть `.f3d` |
| 3MF ✓ | есть общий 3MF |
| STL N из M | у скольких деталей есть актуальный STL |
| Описание ✓ | в txt заполнено `Описание` |
| (позже) Фото | есть фото |

«Полная» — всё ✓, иначе «неполная» и подсказка, чего не хватает.

## 4. Работа с файлами (безопасность)

- Перед любым изменением показываем **план «было → станет»**: переименования, перемещения, новые папки. Ты подтверждаешь кнопкой «Применить».
- **Журнал операций и Undo** для каждого пакета действий.
- **Ничего не удаляем навсегда.** Дубли и мусор уезжают в `_to_delete/`, старые версии — в Корзину macOS.
- Конфликт имён: не затираем, добавляем суффикс и предупреждаем.
- До шага «перемещение с подтверждением» приложение диск только читает.

### 5.1 Главное окно

Эталон раскладки и стопки папок — интерактивный макет `design/window-mockup.html` (22.11.2026).

- **Боковая панель** — плавающая, отдельно от контента, ширина ~120 pt, отступ 8 pt от краёв окна, верх сразу под кнопками окна (иконки на одной вертикали с первой кнопкой):
  - Избранное;
  - «Разобрать» со счётчиком;
  - Библиотека — раскрывающееся дерево (Мои модели → категории → коллекции → группы, Скачанные), папки `Версии/` скрыты;
  - Теги (четыре статуса со счётчиками) и «Что значат теги».
- **Тулбар-капсулы:** назад/вперёд · сетка/список · сортировка · «Новая папка».
- **Поиск моделей** — не в боковой панели: капсула ~150×20 pt в левом верхнем углу основной области, на одной линии с верхом панели. Окончательное место решим отдельно.
- **Стопка папок пути** вместо хлебных крошек (под поиском):
  - каждый уровень — папка: задняя стенка с корешком (скруглён слева, справа плавно стекает вниз), белый лист выглядывает полоской, передняя стенка во всю ширину (~35 pt); все углы мягкие (`.continuous`);
  - каждая следующая папка ложится поверх предыдущей: сдвиг вниз ~7 pt, корешок сдвигается вправо на ширину корешка — корешки читаются как путь;
  - цвет по глубине: текущая яркая, предыдущая темнеет (~70%), все дальше — серые и темнеют с каждым уровнем; лист затемняется вместе с папкой;
  - клик по корешку поднимает на этот уровень, с анимацией;
  - при глубокой вложенности показываем последние 3–4;
  - открыто: цвета корешков — по типам папок (категория/коллекция/группа) или свои цвета уровней, как в макете; что лежит на передней стенке; куда ставить тулбар-капсулы (вероятно, в строку с поиском).
- **Карточки фиксированного размера** (124 pt), длинные имена обрезаются троеточием.
  - Категория и группа — папка: задняя стенка с вкладкой, белый лист, передняя стенка с превью.
  - Коллекция — оранжевая папка или стопка.
  - Модель — карточка-превью с бейджем версии и статусом.

### 5.2 Сортировка

По имени (А–Я) · по дате добавления · по дате изменения (= «недавние») · по размеру файла · по типу (сначала коллекции и группы, потом модели). В тулбаре выбирается одна, плюс направление по возрастанию или убыванию.

### 5.3 Экран коллекции

- Шапка: превью из 3MF, описание из txt, заполненность, кнопки **В слайсер · Открыть Fusion · Заметка · В Finder**, «Сделать коллекцией».
- Ниже группы, потом детали-модели.

### 5.4 Экран модели

- Большое превью с бейджем версии.
- Имя файла, собранное по правилу, и под ним разбор по частям (название, параметры, коллекция, версия).
- Статус: сегмент-переключатель из четырёх значений.
- Файлы версии: STL · 3MF · Fusion (у детали — ссылка на F3D коллекции).
- Кнопки **В слайсер · Fusion · Finder**.
- Таймлайн версий с заметками: клик по версии показывает её файлы, поле «Дописать», зона для перетаскивания новой версии, «Очистить старые версии».

### 5.5 Разбор (главная фишка)

- Слева файлы из `_Разобрать`, сгруппированные по похожим именам, дубли помечены.
- Справа форма для выбранной группы: куда положить, название, параметры, порядок версий (перетаскиванием), актуальная версия.
- Кнопка «Показать план», дальше экран плана.

### 5.6 Прочее

- План изменений: таблица «было → станет», конфликты подсвечены, «Применить / Отмена».
- Журнал / Undo: простой список операций.
- Настройки: корневая папка, разделитель имени, слайсер по умолчанию (OrcaSlicer / Orca-Flashforge / Flash Studio).

## 6. Стек

| Что | Чем |
|---|---|
| UI | SwiftUI, macOS 26, Xcode |
| Доступ к диску | **без sandbox** (личное приложение, не для App Store) |
| Индекс и кэш превью | SwiftData (SQLite), всегда пересобирается из диска |
| Превью 3MF | достать `Metadata/plate_1.png` из zip |
| Превью STL | Model I/O + SceneKit, рендер в фоне, кэш PNG |
| Превью Blend | встроенный thumbnail из `.blend` (позже) |
| Теги | `URLResourceValues.tagNames` (теги Finder) |
| Файловые операции | `FileManager` (move, rename, `trashItem`) + журнал |
| Слежение за папкой | FSEvents (v0.2) |
